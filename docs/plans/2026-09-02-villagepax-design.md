# Дизайн-документ: «Village Pax»

**Дата:** 2026-09-02
**Платформа:** Minecraft 1.20.1, Fabric
**modid:** `villagepax` · корневой пакет `com.villagepax`
**Статус:** черновик, разделы обсуждаются

---

## 0. Главная идея

MineColonies и Millénaire описывают **одну и ту же сущность** — поселение со зданиями, жителями, ресурсами и уровнями развития. Различие только в том, **кто им управляет**:

| | MineColonies | Millénaire |
|---|---|---|
| Владелец | игрок | ИИ |
| Стройка | билдер по схеме, блок за блоком | по плану деревни |
| Смысл игры | построить свою колонию | жить рядом с чужой культурой |

Отсюда центральное архитектурное решение мода:

> **Один движок поселения — два драйвера.**
> `Settlement` — общая структура данных. `PlayerColonyController` реализует MineColonies-геймплей (игрок решает, что строить). `AutonomousVillageController` реализует Millénaire-геймплей (деревня решает сама). Всё остальное — здания, жители, профессии, стройка, экономика, квесты, дипломатия — работает одинаково для обоих.

Второе центральное решение:

> **Народ (Culture) — это данные, а не код.**
> Новый народ = папка в датапаке: JSON + `.nbt`-схемы + текстуры. Java-кода на добавление народа — ноль.

Без этого невозможно вытянуть заявленный размах (исторические народы + гномы + пони + майя + боги + война). С этим — мод растёт контентом, а не переписыванием.

### Сериализация

Никаких сторонних JSON-библиотек. Всё — на **ванильных `Codec`/`DataResult`** (Mojang DFU): один `Codec` описывает и загрузку из датапака, и сохранение в NBT, и передачу по сети. Это экономит примерно треть кода на каждой сущности.

### Замечание по окружению

В системе выставлено `_JAVA_OPTIONS=-Xmx16G`. Это подхватывается **каждым** JVM-процессом, включая Gradle-демон и оба рантайма игры. Работать будет, но память резервируется щедро; при проблемах — снять переменную и задавать память точечно в `gradle.properties`.

## 3. Архитектура

### Слои

```
data/      Датапак: культуры, здания, профессии, квесты,
           планы деревень, схемы .nbt
              │  Codec, перезагрузка по /reload
core/      Реестры типов: CultureType, BuildingType,
           ProfessionType, QuestType, TraitType
              │
sim/       SettlementManager (PersistentState на ServerLevel)
           Settlement ── Building ── Citizen ── Warehouse
           PlayerColonyController | AutonomousVillageController
           DiplomacyManager, QuestManager, EconomyTicker
              │
entity/    CitizenEntity — временное «тело» жителя
           Brain + Behaviors + Sensors, JobStateMachine
              │
net/       Пакеты по подписке: клиент получает срез данных
           только того поселения, чей экран открыт
              │
client/    GUI колонии, HUD, рендер жителей, карта поселения
```

### Железные правила

1. **Вся симуляция — на сервере.** Клиент не считает ничего, только рисует. Это единственный способ не переписывать мод при выходе в мультиплеер.
2. **Житель — это данные, энтити — временное тело.** `Citizen` существует всегда, `CitizenEntity` спавнится только при загруженном чанке и деспавнится при выгрузке, сбрасывая состояние обратно в данные. Именно на этом ломается производительность у существующих модов.
3. **Ни одной ссылки на классы клиента в общем коде.** Иначе падение выделенного сервера.
4. **Никаких статических изменяемых полей.** Всё состояние — внутри `Settlement`, привязанного к миру, иначе ломается переключение между сохранениями.

## 4. Модель данных

```java
Settlement {
    UUID              id;
    ResourceLocation  culture;          // villagepax:norman
    Owner             owner;            // PLAYER(uuid) | AUTONOMOUS
    BlockPos          center;           // ратуша
    int               level;            // 1 хутор → 2 деревня → 3 город → 4 столица
    String            name;             // из name pool культуры
    List<Building>    buildings;
    List<Citizen>     citizens;
    Warehouse         warehouse;        // виртуальный склад + реальные сундуки
    Treasury          treasury;         // монеты культуры
    Relations         relations;        // отношения к игрокам и поселениям
    ChunkClaim        claim;            // занятые чанки
    Stats             stats;            // еда, счастье, безопасность, престиж
    List<QuestState>  activeQuests;
    FaithState        faith;            // отношения с пантеоном
}

Building {
    UUID              id;
    ResourceLocation  type;             // villagepax:norman/lumberjack
    int               level;            // 1..5
    BlockPos          anchor;
    Rotation          rotation;
    BuildProgress     progress;         // PLANNED | BUILDING | DONE | DAMAGED
    List<UUID>        workers;
    Container         localStorage;
    List<BlockPos>    poi;              // рабочие места, кровати, двери
}

Citizen {
    UUID              id;
    String            firstName, lastName;
    ResourceLocation  culture;
    Gender            gender;
    int               ageTicks;
    Family            family;           // родители, супруг, дети
    ResourceLocation  profession;
    Map<Skill,Integer> skills;          // сила, ловкость, ум, выносливость, харизма
    int               happiness, health, saturation;
    UUID              home, workplace;
    JobState          jobState;         // персистентная машина состояний работы
    Schedule          schedule;         // распорядок дня
    UUID              spawnedEntity;    // nullable: если сейчас есть тело
}
```

**Хранение.** `SettlementManager extends PersistentState`, привязан к `ServerLevel`. Сериализация через `Codec` в NBT. Резервные копии данных поселения — раз в N сохранений, чтобы одна повреждённая запись не убивала колонию на 200 часов игры.

### Система трейтов — как уживаются майя, гномы и пони

Трейт — это **зарегистрированный в коде модификатор поведения**, который культура включает одной строкой в JSON. Именно трейты дают радикально разный геймплей без ветвлений `if (culture == DWARF)` по всему коду.

| Трейт | Эффект |
|---|---|
| `builds_underground` | планировщик деревни ищет площадку в горе и копает вниз (гномы) |
| `builds_in_canopy` | здания ставятся на высоте, соединяются мостами (эльфы) |
| `grazing` | часть жителей не работает в зданиях, а пасётся на пастбище (пони) |
| `stone_masonry` | +скорость стройки из камня, −из дерева |
| `mounted_warfare` | военные отряды садятся верхом |
| `terrace_farming` | фермы ступенчатые, работают на склонах (майя) |
| `river_dependent` | деревня генерируется только у воды |

Трейты — точка расширения №1. Каждый новый — небольшой класс, но обслуживает любое число культур.

## 6. Схемы зданий и строительство

### Формат схем

**Ванильный structure NBT** (`.nbt`, создаётся Structure Block'ом в игре) + JSON-метаданные. Свой формат не изобретаем: ванильный уже умеет блок-энтити, повороты, поддерживается инструментами, и его можно править прямо в игре.

### Блоки-маркеры

Внутри схемы расставляются служебные блоки мода. Билдер при постройке заменяет их на воздух и регистрирует точку интереса:

| Маркер | Смысл |
|---|---|
| `villagepax:marker_workstation` | рабочее место профессии |
| `villagepax:marker_bed` | место кровати жителя |
| `villagepax:marker_storage` | сундук здания |
| `villagepax:marker_door` | точка входа для навигации |
| `villagepax:marker_decor` | слот под случайный декор (вариативность) |

Так одна схема описывает и геометрию, и логику здания.

### Метаданные здания

```json
{
  "display_name": "villagepax.building.lumberjack",
  "category": "production",
  "max_level": 5,
  "levels": [
    {
      "level": 1,
      "structure": "villagepax:norman/lumberjack_lvl1",
      "requires": { "minecraft:oak_log": 64, "minecraft:cobblestone": 32 },
      "worker_slots": 1,
      "unlocks_recipes": ["villagepax:plank_batch"]
    }
  ],
  "requires_settlement_level": 1,
  "requires_buildings": ["villagepax:norman/town_hall:1"]
}
```

### Как идёт стройка

1. Игрок (или ИИ-контроллер) выбирает здание и точку. Показывается **голограмма** схемы с поворотом — клиентский рендер, без изменения мира.
2. Создаётся `Building` со статусом `PLANNED`, в склад ставится заявка на материалы.
3. **Курьер** таскает материалы со склада на стройплощадку.
4. **Билдер** идёт по отсортированному списку блоков схемы и ставит их по одному раз в N тиков. Порядок важен, чтобы стройка выглядела как стройка, а не как случайные блоки, и задан он **направлением обхода, а не перечислением фаз**: расчистка сверху вниз, потом всё несущее снизу вверх, потом обстановка. Фундамент лежит ниже стен, крыша выше — значит обход по возрастанию высоты выкладывает их в нужном порядке сам, и подсистема распознавания крыш не нужна (её и нельзя написать надёжно: у мансарды крыша и есть стена). Маркеры не ставятся, а становятся точками интереса. Реализовано в задаче 1.5, см. [под-план](2026-09-07-task-1.5-schematics.md).
5. Апгрейд: схема уровня N+1 накладывается поверх; билдер сносит лишнее и достраивает.
6. Разрушенное здание (война, крипер) переходит в `DAMAGED` — билдер чинит по той же схеме.

**Оптимизация:** список блоков считается один раз при планировании и кэшируется, не пересчитывается каждый тик. Установка блоков идёт пачками с ограничением на количество block updates за тик.

## 7. Жители: ИИ, работа, жизненный цикл

### Двухуровневый ИИ

| Уровень | Где живёт | Частота | Что решает |
|---|---|---|---|
| **Стратегический** | `Citizen.jobState` (данные) | раз в 20–100 тиков | что делать: идти на работу, есть, спать, нести груз |
| **Тактический** | `CitizenEntity.Brain` (энтити) | каждый тик | как именно: путь, взгляд, анимация, уклонение |

Разделение критично: стратегия переживает выгрузку чанка, тактика — нет. Житель, начавший рубить лес, после перезахода в мир продолжит с того же места.

Тактика знает про **дорогу**: шаг вне блоков из тега `villagepax:preferred_path` стоит на один блок пути дороже. Ванильный поиск пути не различает траву и мостовую, поэтому без этого все работники идут одной линией напрямик и толкаются; с мощёной улицей путь ложится на неё сам. Надбавка мала намеренно — дорога должна быть удобством, а не лабиринтом. К цели каждый житель подходит со своей постоянной стороны, чтобы двое не метили в один и тот же блок.

### Профессии

Профессия — данные (`professions/lumberjack.json`) + `JobLogic` в коде. Базовые типы job-логики покрывают почти всё:

| Job-логика | Профессии на её основе |
|---|---|
| `GatherJob` | лесоруб, шахтёр, рыбак, травник |
| `FarmJob` | фермер, пастух, садовник |
| `CraftJob` | кузнец, плотник, пекарь, ткач |
| `HaulJob` | курьер, торговец |
| `BuildJob` | строитель, каменщик |
| `GuardJob` | стражник, лучник, всадник |
| `SocialJob` | старейшина, жрец, учитель, лекарь |

Новая профессия чаще всего = JSON поверх существующей логики.

Профессия сама называет своё рабочее место (атрибут `workplace`), когда его имя не совпадает с её собственным: фермер работает на **ферме**, а лесоруб — в **lumberjack**, и второму поле не нужно.

### Работа должна быть видна

У жителя в руке то, чем он занят: строитель держит блок, который ставит, лесоруб топор, фермер мотыгу, курьер свой груз. Это требование к каждой новой профессии, а не украшение: без предмета в руках игрок понимает, что происходит, только по результату — по растущей стене или по исчезающему лесу. Модель поэтому двуногая, а не «селянин»: у того руки сложены на груди навсегда.

### Распорядок дня

Каждый житель имеет расписание из культуры: подъём → работа → обед → работа → досуг → сон. Досуг ведёт на площадь/в таверну/в храм — это то, что делает деревню живой, и стоит дёшево.

### Жизненный цикл

Житель стареет, вступает в брак, заводит детей, умирает от старости, болезни или в бою. Дети растут и занимают вакансии. Это создаёт долговременную привязанность к колонии — и требует аккуратной модели населения, чтобы деревни не вымирали и не взрывались экспоненциально.

*Открытый вопрос: включаем смертность сразу или как настройку. См. §17.*

### Счастье

Счастье жителя складывается из: еда, качество дома, безопасность, близость работы, досуг, отношения в семье, налоги. Низкое счастье → снижение производительности → уход из колонии. Это основной «регулятор сложности» всего мода.

## 8. Автономные деревни

### Генерация

**Не** через ванильную `Structure` — она ставит статичную заготовку, а нам нужно живое поселение, которое строится и растёт.

1. При генерации чанка детерминированно (от сида) отмечаются **места под деревню**: биом, вес культуры, минимальное расстояние до других поселений, пригодность рельефа.
2. Когда игрок подходит на N чанков, `AutonomousVillageController` создаёт поселение: расчищает площадку, ставит стартовые здания уже готовыми, спавнит жителей.
3. Дальше деревня живёт и растёт по общему движку — те же билдеры, те же схемы.

Так первое знакомство выглядит как настоящая деревня, а не стройплощадка, но дальнейшее развитие игрок видит своими глазами.

### Рост

Контроллер раз в игровой день оценивает: чего не хватает (еда, жильё, защита, престиж), что позволяет `village_plan` и уровень поселения, есть ли ресурсы — и ставит следующее здание в очередь.

### Симуляция на расстоянии

Незагруженная деревня тикает раз в игровой день **упрощённой моделью**: производство и потребление считаются формулой, без энтити и без блоков. Стройка идёт в абстракции и «материализуется» при возвращении игрока.

Без этого мир мёртвый: ушёл на 10 000 блоков — вернулся, а всё как было. С этим — вернулся через игровой месяц, а хутор стал городом.

## 9. Дипломатия и война

### Матрица отношений

Четыре уровня, все хранятся отдельно:

| Отношение | Пример |
|---|---|
| народ ↔ народ | гномы исторически не любят эльфов |
| поселение ↔ поселение | конкретные две деревни поссорились из-за границы |
| игрок ↔ поселение | репутация: чужак → знакомый → друг → почётный житель |
| игрок ↔ народ | средневзвешенное по поселениям народа |

### Дипломатические действия

Подарки, выполнение квестов, торговые соглашения, пакт о ненападении, союз, требование дани, объявление войны, вассалитет. Каждое действие меняет несколько уровней матрицы сразу — подарок конкретной деревне слегка поднимает и отношение всего народа.

### Война

- **Причины:** спор за территорию (пересечение claim'ов), исторические счёты, агрессия игрока, требование дани, религиозный конфликт.
- **Механика:** формируются `WarParty` — отряды с целью (разорить здание, убить жителя, захватить ратушу). Отряд — это данные; энтити спавнятся при подходе к загруженной зоне.
- **Осада:** атака на здания, `DAMAGED`-состояние, гибель жителей, разграбление склада.
- **Исход:** контрибуция, потеря зданий, смена владельца поселения (`Owner` меняется, культура остаётся — завоёванная деревня платит дань).
- Колония игрока — полноценный участник, со своей стражей и укреплениями.

## 10. Квесты, репутация и боги

### Квесты как данные

```json
{
  "id": "villagepax:norman/founding_chain/1",
  "giver": { "profession": "villagepax:elder" },
  "conditions": { "min_reputation": 0, "settlement_level": 1 },
  "objectives": [
    { "type": "deliver", "item": "minecraft:wheat", "count": 32 }
  ],
  "rewards": [
    { "type": "reputation", "amount": 15 },
    { "type": "item", "item": "villagepax:denier", "count": 20 },
    { "type": "unlock_quest", "quest": "villagepax:norman/founding_chain/2" }
  ],
  "dialogue": "villagepax.quest.founding.1"
}
```

### Типы целей

Принести предмет, доставить в другую деревню, убить, построить, разведать точку, сопроводить NPC, дипломатический (помирить две деревни), ритуальный (принести жертву в храме).

### Динамические квесты

Помимо написанных цепочек — квесты, порождаемые состоянием мира: голод в деревне → «принеси еды»; идёт война → «убей вражеского командира»; строится здание → «принеси 64 камня». Это то, что делает Millénaire бесконечным, и стоит дёшево при готовом движке.

### Боги и чудеса

Пантеон — данные культуры. Игрок набирает благосклонность жертвами в храмах и длинными цепочками квестов. Награды:

- **Благословения** — временные баффы поселению (урожайность, скорость стройки, защита).
- **Чудеса** — разовые крупные эффекты (дождь, исцеление, гнев на врага).
- **Артефакты** — уникальные предметы за завершённые цепочки, главная долгосрочная цель.

## 11. Производительность

Это то, что убивает подобные моды. Закладывается с первого дня, а не «оптимизируем потом».

| Риск | Решение |
|---|---|
| Сотни энтити | Пул: не больше N заспавненных жителей на поселение; остальные — в данных |
| Поиск пути душит TPS | Общая очередь pathfinding с лимитом запросов за тик + кэш маршрутов между зданиями |
| Тяжёлые решения каждый тик | Стратегический ИИ раз в 20–100 тиков, со смещением по хешу UUID (чтобы не совпадали) |
| Планирование стройки | В отдельном потоке, результат возвращается в главный поток |
| Много поселений в мире | Абстрактная симуляция для выгруженных, полная — только рядом с игроком |
| Массовая установка блоков | Пачками, с лимитом block updates и без лишних `notifyNeighbors` |
| GUI гонит данные | Синхронизация по подписке: только открытый экран, только изменившиеся поля |

**Бюджет:** одно активное поселение среднего размера рядом с игроком — не больше 5 мс на тик.

## 12. Мультиплеер и совместимость

- Всё server-authoritative с первого коммита. Одиночная игра в Minecraft — это встроенный сервер, так что «сначала SP, потом MP» экономит ноль времени и стоит потом переписывания.
- Права: владелец колонии, доверенные игроки, гости. Защита claim'а от постороннего разрушения — настраиваемая.
- Совместимость с генерацией мира: поселения не спавнятся вплотную к ванильным структурам; расстояние настраивается.
- Совместимость с модами: культуры могут ссылаться на блоки других модов через теги, так что чужие блоки работают в схемах, если мод установлен; иначе — фолбэк на ванильный аналог.

## 14. Тестирование

- **JUnit 5** — чистая логика без Minecraft: экономика, планировщик стройки, дипломатия, разбор датапаков.
- **Fabric GameTest** — сценарии в игре: основать колонию, построить здание, нанять жителя, пережить перезагрузку мира, пережить выгрузку чанка.
- **Нагрузочный сценарий** — мир с 5 поселениями, замер TPS, регресс-порог в CI.
- **GitHub Actions** — сборка + тесты на каждый коммит.

Тест «сохранил → вышел → зашёл → всё на месте» пишется в первую же неделю. В модах такого класса потеря состояния — самый частый и самый болезненный баг.

## 17. Открытые вопросы

1. **Валюта.** Своя монета у каждого народа (разнообразие, сложнее обмен), одна общая (проще), или чистый бартер?
2. **Как игрок основывает колонию.** Крафтит блок ратуши, покупает у NPC, или получает как награду за первый квест у чужой деревни (мягкое введение в мод)?
3. **Может ли игрок жить внутри чужой деревни** как гражданин, не основывая свою колонию? Это отдельная ветка геймплея, ближе всего к оригинальному Millénaire.
4. **Что даёт уровень поселения** — какая именно награда за апгрейд, кроме доступа к новым зданиям.
5. **Как игрок ведёт войну** — командует ли он отрядами напрямую или только объявляет цель.
6. **Глубина жизни жителя** — насколько подробно моделируем семью, характер и отношения между жителями.

### Решено по ходу обсуждения

- Название: **Village Pax**, modid `villagepax`.
- Первый народ: **норманны**.
- Смертность: **включена**, с настройкой в конфиге.
- **Вход в мод — через квесты чужой деревни.** Игрок находит норманнскую деревню, выполняет
  стартовую цепочку, набирает репутацию до «друга» и получает от старейшины чертёж ратуши.
  Обязательная подстраховка: чертёж также крафтится из дорогих материалов — иначе на неудачном
  сиде мод не запускается вовсе.
- **Гражданство в чужой деревне** (работать на них, получить дом, дорасти до старейшины) —
  ветку закладываем в архитектуру, реализуем в фазе 3, в срез 0.1 не берём.
- **Каждый уровень поселения даёт новый глагол, а не большее число.** Хутор — тебя не замечают;
  деревня — появляешься на дипломатической карте, приходят чужие караваны; город — стража,
  союзы, право требовать дань; столица — сюзеренитет над поселениями своего народа, посольства.
- **Престиж — валюта уровней.** Начисляется и за здания со счастьем, и за квесты чужих народов,
  артефакты, союзы и выигранные войны. Гейт средней жёсткости: материалы дают около двух третей
  условия, отношения с соседями — треть. Именно престиж сшивает половину MineColonies
  с половиной Millénaire в один мод.
- **Валюта — одна общая.** От отношений зависят не курсы размена, а цены: друзья продают дешевле
  и покупают дороже, враги не торгуют. Бартер остаётся для раннего этапа.
- **Полный экономический контур в колонии:** казна платит жителям жалование, игрок задаёт ставку
  налога (высокая ставка бьёт по счастью). Деньги ходят по кругу: жалование → житель тратит
  на рынке → покупает продукцию своей же колонии → налог возвращается в казну. Если товара нет
  своего, житель покупает у каравана и монета утекает — так самодостаточность становится
  экономической целью, а рынок нужным зданием.
- **Командование в войне — только приказы с карты в ратуше**, без знамени и без выделения
  отрядов. Игрок назначает цели, стража исполняет; лично драться никто не мешает, но исход
  боя решает не он. Следствие: качество боевого ИИ критично — игрок не сможет вытащить бой
  руками, если солдаты застревают или лезут по одному. Заложить время на это в фазе 3.
- **Поражение больно, но обратимо.** Здания уходят в `DAMAGED` и чинятся билдером, а не
  исчезают; жители гибнут, но колония выживает. Проигранная война — дань и вассалитет,
  а не удаление колонии. Иначе первый серьёзный рейд заставляет игрока удалить мир.
- **Боги независимы** — жертва одному не злит другого, угождать можно всем. Чтобы пантеон
  не выродился в чек-лист, благосклонность набирается медленно: за прохождение реально
  успеть поднять одного-двух. Выбор остаётся, но за счёт нехватки времени, а не наказания.
- **Жители: характеры сразу, отношения позже.** Черты характера (ленивый, честолюбивый,
  набожный, трус) — в 0.1–0.2, дёшево и сразу делает жителей различимыми. Дружба и вражда
  между жителями со влиянием на работу — фаза 4, дорого в отладке.
- **Квесты трёх сортов:** написанные цепочки народа (8–12 шагов, ведут к артефакту и титулу),
  динамические из состояния мира, дипломатические от других поселений.
